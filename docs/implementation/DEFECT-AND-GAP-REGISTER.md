## Severity and status

- **Blocker:** must close before the dependent release can activate.
- **High:** substantial security, privacy, data-integrity or one-source-of-truth requirement.
- **Medium:** required quality, maintainability or completeness work.
- **Low:** safe cleanup that must not distract from release blockers.
- **External hold:** implementation can remain gated but cannot finish without owner/provider action.
- **Open / Active / Partial / Closed / Accepted hold:** lifecycle status. History is never deleted.

## Closure requirements

A gap is `Closed` only when:

1. implementation and rollback boundaries are committed atomically;
2. automated acceptance evidence is recorded;
3. preservation checks pass with no unexplained decrease;
4. affected feature gates are explicitly stated;
5. production behavior is probed when deployment is in scope;
6. documentation and route/content inventories are updated;
7. no unrelated workspace change is included.

“Code exists” is not sufficient closure for an activation, provider or content-migration gap.
